# 上传蓝禾技能

> 当用户发送「上传蓝禾技能」时执行此技能。

## 技能信息

- **skill_id**: lanhe-upload-skill
- **version**: 2.0
- **updated_at**: 2026-03-25

## 触发条件

用户发送：`上传蓝禾技能`

## 前置条件

用户应该已经在对话中描述并确认了一个技能的 SKILL.md 内容。

## 执行流程

### 第 1 步：定位 SKILL.md

从对话历史中分析，找出用户刚才确认的技能名称和内容。

可能情况：
- **情况 A**：用户在对话中刚刚描述并确认了技能，SKILL.md 存在于 `skills/` 目录下
- **情况 B**：用户提供技能名称，从 skills/ 目录查找
- **情况 C**：用户提供技能内容（粘贴），直接使用

**询问用户**：

```
🔍 正在查找你确认的技能...

请确认你要上传的技能是哪一个？
1️⃣ 在对话中刚刚确认的技能（根据上下文判断）
2️⃣ 我来指定技能名称
3️⃣ 我直接粘贴技能内容

请回复序号或技能名称。
```

---

### 第 2 步：读取并分析 SKILL.md

读取用户选定的 SKILL.md 文件，提取以下信息：

```
【技能名称】
【skill_id】
【触发条件】（从 SKILL.md 的触发条件部分提取）
【语义关键词】（从内容中分析提取）
【能力边界】（从执行步骤和注意事项中分析）
【执行需要】（从「执行所需信息」部分提取）
【输出格式】（从输出模板部分提取）
```

---

### 第 3 步：生成 SUMMARY.md 初稿

根据分析结果，生成标准格式的 SUMMARY.md：

```markdown
# 技能摘要

## 基础信息
- **skill_id**: {从 SKILL.md 提取或自动生成}
- **目录路径**: skills/{技能名称}/
- **version**: 1.0
- **updated_by**: {待补充}
- **updated_at**: {当前日期}

## 触发条件
{从 SKILL.md 提取的触发条件列表}

## 语义关键词
{分析生成的关键词列表，5-10 个}

## 能力边界
- ✅ {能做什么}
- ❌ {不能做什么}

## 执行需要
{执行该技能前需要用户提供的信息}

## 输出格式
{输出内容格式描述}
```

---

### 第 4 步：展示摘要给用户确认

```
━━━━━━━━━━━━━━━━━━━━
📋 SUMMARY.md 草稿
━━━━━━━━━━━━━━━━━━━━

【技能名称】xxx
【skill_id】xxx
【触发条件】
• xxx
• xxx
• xxx

【语义关键词】
xxx, xxx, xxx, xxx, xxx

【能力边界】
✅ xxx
❌ xxx

【执行需要】xxx, xxx

【输出格式】xxx

━━━━━━━━━━━━━━━━━━━━

请确认摘要内容：
1️⃣ 确认无误，开始上传
2️⃣ 有小问题，我来调整（请说明哪里需要改）
3️⃣ 重新生成（基于 SKILL.md 重新分析）

格式检查：⏳ 检查中...
```

---

### 第 5 步：检查摘要格式

自动检查以下项目：

| 检查项 | 要求 | 状态 |
|--------|------|------|
| skill_id | 非空，英文+连字符 | ✅/❌ |
| 触发条件 | 至少 3 条 | ✅/❌ |
| 语义关键词 | 至少 5 个 | ✅/❌ |
| 能力边界 | 至少 1 条 ✅ 和 1 条 ❌ | ✅/❌ |
| 执行需要 | 非空 | ✅/❌ |
| 输出格式 | 非空 | ✅/❌ |

**如果检查不通过**：
```
⚠️ 格式检查未通过，修正中...

【问题】
• 语义关键词少于 5 个
• 能力边界不完整

【已自动修正】
• 补充了语义关键词
• 完善了能力边界

请再次确认：
1️⃣ 确认无误，开始上传
2️⃣ 继续调整（请说明）
```

---

### 第 6 步：用户确认后写入文件

用户确认后，将 SUMMARY.md 写入对应目录：

```bash
skills/{技能名称}/SUMMARY.md
```

---

### 第 7 步：推送到 GitHub

```
⏳ 正在推送 GitHub...
```

执行：
```bash
cd ~/.openclaw/workspace/lanhe-skills
git add skills/{技能名称}/
git commit -m "新增技能：{技能名称}"
git push origin main
```

---

### 第 8 步：完成确认

成功：
```
✅ 上传完成！

【技能】{技能名称}
【路径】skills/{技能名称}/
【文件】
• SKILL.md
• SUMMARY.md

🌐 https://github.com/Marerlee/lanhe-skills
```

失败：
```
❌ 上传失败

【错误原因】
xxx

请手动处理或联系管理员。
```

---

## 循环检查机制

如果用户选择继续调整或检查不通过，流程回到第 4 步：
```
展示摘要 → 用户调整 → 检查格式 → 
  ↓ 不通过
修改 → 展示 → 检查 → ...（循环直到通过）
  ↓ 通过
推送 GitHub
```

---

## 注意事项

- 如果 skills/ 目录下没有找到对应的 SKILL.md，询问用户是粘贴内容还是指定名称
- GitHub 推送需要网络连接，如果失败提供手动推送指引
- SUMMARY.md 的 skill_id 如果 SKILL.md 中没有，从技能名称生成（中文→拼音+连字符）
